## 📝 Project Overview
Each month, a credit card issuer can contact only 20% of its total portfolio for preventive collection management. This project trains a machine learning model to estimate the probability of default for each customer for the upcoming month, sorting prioritized contacts based on **expected loss** (probability × balance). The model's performance is strictly compared against current business heuristics using the same contact capacity.

### Key Result:
On an unseen test set of **6,002 customers**, with a fixed operational capacity of 1,200 contacts, the model captured **NT$ 51.5 million** in outstanding debt from customers who indeed defaulted. This represents a **17.7% improvement** over the best current business rule (with a 95% bootstrap confidence interval ranging from **12.4% to 23.6%**). Detailed insights and financial analyses are fully documented in the final report.

## 📊 Key Results Summary (Holdout Set)
Below is a quick overview of how the final Machine Learning model (`HistGradientBoostingClassifier`) performs on the unseen holdout set compared to standard business baselines at the 20% capacity limit:

* **Primary Metric (Outstanding Debt Captured):** 
  * **Model (M1 - Expected Loss Ranking):** **NT$ 51.47 Million** *(Winner)*
  * **Business Rule (B1 - Delay Heuristics):** **NT$ 43.74 Million**
  * **Relative Benefit:** **+17.7% net improvement** (95% CI: `[12.4%, 23.6%]`).
* **Model Performance (Discrimination & Calibration):**
  * **PR-AUC:** **0.547** (Bootstrap 95% CI: `[0.513, 0.582]`) vs. a random baseline prevalence of `0.221`.
  * **ROC-AUC:** **0.781** (Bootstrap 95% CI: `[0.765, 0.796]`).
  * **Brier Score:** **0.134** (well-calibrated via Isotonic Regression, ECE gap: `0.009`).
* **Operational Statistics:**
  * **Recall @ 20%:** **48.4%** (captures nearly half of all defaults by contacting just 20% of customers).
  * **Lift @ 20%:** **2.42x** (performs more than double than a random selection strategy).

## ⚠️ Crucial Considerations
* **Version Control:** Ensure you use the exact library versions in `requirements.txt`. Different versions of `scikit-learn` will yield slight variations in numeric results (e.g., in v1.9.1 the test set PR-AUC rises to 0.550 instead of 0.547, changing the relative advantage over the business rule from 12.4%-23.6% to 13.5%-24.5%).
* **Optional SHAP:** Section 7.6bis relies on the `shap` library. If missing, the notebook will attempt automatic installation. If it fails, the notebook dynamically bypasses the section without breaking dependencies.
* **No Data Leakage:** The test set is isolated immediately after basic loading. All modeling, engineering, and threshold-tuning choices are evaluated strictly via Cross-Validation on the training set.
* **Financial Assumptions:** Parameters like LGD (60%), contact cost (NT$ 200), and contact effectiveness (20%) are configurable within `CONFIG` and should be calibrated with the business team.
* **Project Scope:** Setup costs (NT$ 500,000 initial, NT$ 50,000/month recurring) are business projections documented in the PDF and are not outputted by the python script.
